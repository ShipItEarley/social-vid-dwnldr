# Video Downloader

A small local browser app for downloading social videos, Instagram photos and stories, and TikTok photo slideshows. New downloads live inside `~/Documents/Video-Download/`, with platform folders named Instagram, YouTube, TikTok, and Twitter; history stays in the app's ignored `.state/` folder. Individual videos, photos, and stories go directly into the platform folder. Each TikTok slideshow and Instagram carousel gets its own folder named from its title or caption. Titles are shortened to at most 60 characters, with creator-name fallback and numbered suffixes for duplicate files or folders. Slideshow images retain their original bytes and format and include ordered slide numbers in their filenames. History persists each job's actual folder, including slideshow and carousel subfolders and older save locations.

Visual thesis: a quiet off-white work surface, dark type, and one green action color, with the link field as the main focus.

Content plan: compact app header; paste-link form and optional browser-session selector; save destination; recent downloads with progress, errors, retry, and file actions.

Interaction thesis: a short entrance fade, clear button/focus transitions, and smooth progress changes. Reduced-motion preferences disable animation.

The Python standard library serves the app on loopback only. A serial queue runs yt-dlp in a subprocess with a time limit (30 minutes for YouTube, three minutes for other platforms); no passwords are collected. Browser-session use is opt-in for each download. Download history is persisted atomically. Each job downloads into a hidden temporary folder inside its platform folder. Completed files are published without overwriting existing files, and temporary sequence numbers keep same-titled carousel videos separate until publication. The server only serves files explicitly recorded for that job from its persisted folder, rejecting symlinks and path traversal. Requests require a local host and mutations require a session token. Instagram Reel, photo/video post, story, highlight, and legacy TV links are supported, along with TikTok full video/photo URLs and short share links. YouTube watch, short share, Shorts, mobile, Music, embed (including privacy-enhanced embeds), legacy video, and recorded live links all become one canonical watch URL. Only the selected full video is downloaded; timestamps, tracking, and playlist context are discarded. YouTube downloads use Deno or Node.js for JavaScript challenges. Profile, channel, playlist-only, and clip URLs are rejected with guidance. YouTube active and upcoming streams are rejected after reading their metadata; recordings are allowed.

TikTok photo extraction extends yt-dlp's existing TikTok page reader, preserving its session and challenge handling. Short links resolve to a single photo or video post. Original image URLs are tried in order across CDN mirrors; the file extension is detected from image bytes. Incomplete downloads remain temporary, completed slides are published even if another fails, and missing slides produce an error with the saved count. Progress and history distinguish photos from videos.

Instagram extraction extends the existing post and story readers to retain photos, using their largest image candidate first. Video posters never become standalone photos. Mixed carousels retain item order. A full story URL selects only that item; a username story URL saves the available collection. Highlight collections are supported. Stories that require a login use the explicitly selected browser session. Empty or expired stories produce an actionable error. The Instagram photo adapter and TikTok slideshows share the same image transfer and validation code.

Verification: test link validation, job lifecycle and restart recovery, error handling, file isolation, HTTP API protections, real video and photo transfers from local fixtures, and the browser interface. Live platform downloads can be checked separately; login and rate-limit failures are reported as errors.

X/Twitter post URLs from x.com and twitter.com normalize to x.com with tracking removed. Extraction uses yt-dlp's existing Twitter reader and optional browser session. Plain post links save all available videos, while /video/N links retain the selected media index. Files go directly into Twitter/. Photo links, profiles, and Spaces are rejected before queueing; inaccessible or video-free posts report an error. Local fixtures verify real video transfers, multiple videos, and selection from mixed media posts.
